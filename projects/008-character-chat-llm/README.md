# Character Chat LLM

軽量LLMを用いたキャラクター会話を題材に、プロンプトエンジニアリング、Few-shot、LoRAによるキャラクター表現の再現性と、回答品質・指示追従への影響を比較する実験。

## Overview

キャラクターらしい会話を実現する方法として、プロンプトによる指示やFew-shot、LoRAによる追加学習が考えられる。

本実験では、軽量LLMを用いて各手法による出力を比較し、キャラクターの口調や表現の再現性、回答内容の自然さ、指示への追従にどのような違いが見られるかを確認する。

また、Gemini APIにもローカルLLMと同じキャラクター設定・返答ルール・Few-shot例を与え、プロンプトベースのキャラクター会話を比較する。

## Tech Stack

- Python
- PyTorch
- Hugging Face Transformers
- PEFT
- TRL
- Unsloth
- Qwen2.5-0.5B-Instruct
- Gemini API
- Google Colab

## Experiment

### 1. Model and Character Settings

ローカルLLMには `Qwen/Qwen2.5-0.5B-Instruct` を使用した。

キャラクターはC言語、Python、HTMLの3種類を用意し、それぞれの性格・口調・返答ルールを設定した。  
LoRAの学習には、自作した各キャラクターの発話データを使用した。

### 2. Comparison Methods

ローカルLLMでは、以下の4条件を比較した。

| Condition | Description |
|---|---|
| Base Model | キャラクター設定を1文で指示 |
| LoRA | キャラクターの発話データを用いて追加学習 |
| Few-shot / Prompt | キャラクター設定、返答ルール、発話例をプロンプトに追加 |
| LoRA + Few-shot | LoRAによる追加学習と、キャラクター設定・返答ルール・発話例を併用 |

さらに、Gemini APIにもFew-shotを含む同じキャラクター設定と返答ルールを与え、参考比較を行った。

### 3. LoRA Training

ベースモデルにはQwen2.5-0.5B-Instructを使用し、Google Colab上でLoRAの学習を行った。

学習データは各キャラクター約80件の発話データとした。PEFTを使用した学習では、4bit量子化を用いるQLoRA構成を採用した。

主な設定は以下のとおり。

| Parameter | Value |
|---|---|
| Base model | Qwen2.5-0.5B-Instruct |
| Training method | PEFT / LoRA |
| Quantization | 4-bit |
| LoRA rank (`r`) | 8 |
| LoRA alpha | 16 |
| LoRA dropout | 0.05 |
| Learning rate | 2e-4 |
| Max training steps | 150 |
| Per-device batch size | 2 |
| Gradient accumulation steps | 4 |
| Max sequence length | 2048 |

### 4. LoRA Implementation: Unsloth and PEFT

当初はUnslothを使用してLoRAの学習を試みた。公式サイトの手順を参考に実装したが、環境や依存関係などの影響もあり、想定どおりに安定して動作させることが難しかった。

その後、Unslothでも学習を実行できたが、動作の安定化と実装の管理を優先し、PEFTを用いた実装に切り替えた。

本実験では、PEFTによるLoRAの学習済みアダプターを読み込み、キャラクターごとに切り替えて推論を行った。

### 5. Evaluation Questions

以下の3種類の質問を用いて出力を比較した。

| ID | Question | Question Type |
|---|---|---|
| Q1 | うどんのおすすめのトッピングを教えて。 | Open-ended question |
| Q2 | 桜は綺麗だね。 | Impression / casual conversation |
| Q3 | とりあえずLoRAやプロンプトをいじってみたけど、本末転倒かな？ | Advice / opinion |

### 6. Generation Settings

ローカルLLMでは、生成時に `do_sample=False` を指定し、サンプリングを無効化した。これにより、確率的なサンプリングによる出力の揺らぎを抑えた条件で比較した。

```python
generated_ids = model.generate(
    **prompt,
    max_new_tokens=512,
    do_sample=False,
)
```

Gemini APIについても、ローカルLLMと同じキャラクター設定、返答ルール、Few-shot例を使用した。ただし、モデルや生成APIが異なるため、生成処理の条件が完全に同一というわけではない。

### 7. Evaluation Criteria

出力を以下の3つの観点から定性的に評価した。

| Evaluation Axis | Description |
|---|---|
| Character Likeness | 一人称、語尾、口調、語彙など、キャラクター固有の表現が再現されているか |
| Naturalness and Coherence | 日本語として自然で、回答内の意味や論理に一貫性があるか |
| Instruction Following and Relevance | 返答ルールを守り、質問の意図に沿った回答を生成しているか |

今回は3問による探索的な比較であり、数値スコアの集計は行わず、出力例から傾向を整理した。

## Results

### 1. Lightweight LLM

#### Base Model

キャラクター設定を1文で指示した場合、キャラクター固有の口調や表現は限定的だった。

また、質問によっては不自然な説明や、質問の意図を十分に捉えられていない回答も確認された。

#### LoRA

キャラクター固有の口調や表現が強く現れる傾向が見られた。一方で、日本語の不自然さや他言語の混在、意味的なつながりが崩れた回答も確認された。

例えば、HTMLキャラクターでは「ウチ」や絵文字を用いた特徴的な口調が現れた一方、うどんの説明に英語やCSSに関連する表現が混ざり、回答内容の一貫性が損なわれるケースがあった。

#### Few-shot / Prompt

発話例や返答ルールを与えても、回答品質やキャラクターらしさが安定して改善する結果にはならなかった。

質問に対して定型的な説明を返すケースや、うどんのトッピングとして不適切なものを挙げるケースなどが見られた。

また、返答ルールとして「2行以内」を指定したが、ローカルLLMでは指示どおりに収まらない出力も確認された。

#### LoRA + Few-shot

LoRAによるキャラクターらしい口調が維持されるケースがあった一方、回答内容の自然さや一貫性が安定して改善する結果にはならなかった。

LoRAとFew-shotを併用することで、キャラクターらしい表現と回答品質の両方を安定して実現できるとは限らないことが分かった。

### 2. Gemini API

Gemini APIでは、同じキャラクター設定・返答ルール・Few-shot例を与えたところ、今回の質問に対して「2行以内」という指示を守る出力が見られた。

また、Pythonキャラクターがうどんのトッピングをプログラミングにたとえたり、HTMLキャラクターが色やCSSの表現に結びつけたりするなど、キャラクター設定を回答に反映できていた。

一方で、キャラクター設定に沿った表現が質問内容に対して過剰になったり、Cキャラクターのように質問をそっけなく退けたりする回答もあった。形式的な指示に従うことと、自然で親しみやすいキャラクター会話を実現することは、必ずしも同じではなかった。

## Discussion

### 1. LoRAによるキャラクター表現の変化

今回の実験では、LoRAによってキャラクター固有の口調や表現が現れやすくなる傾向が見られた。

一方、口調が再現されていても、回答内容が自然で一貫しているとは限らなかった。

このことから、キャラクターの表現を再現することと、質問に対して適切な回答を生成することは、分けて評価する必要があると考えられる。

### 2. Few-shotとプロンプトの効果

軽量LLMでは、Few-shotや返答ルールを追加しても、回答内容や指示への追従が安定して改善する結果にはならなかった。

一方、Gemini APIでは、同じキャラクター設定や返答ルールを与えた場合に、「2行以内」という形式的な指示を守る出力が見られ、質問に応じたキャラクター表現も得られた。

この違いから、プロンプトやFew-shotによる制御のしやすさは、指示の内容だけでなく、使用するモデルの言語理解・文章生成能力にも左右される可能性が考えられる。

ただし、今回はQwen2.5-0.5B-InstructとGeminiという異なるモデルを比較しているため、出力の違いをモデルサイズだけに帰属させることはできない。モデルの学習方法、日本語への対応力、モデルごとの特性なども影響している可能性がある。

### 3. 生成設定の影響

再実験では、ローカルLLMの生成時に `do_sample=False` を指定し、サンプリングによる出力の揺らぎを抑えた。

この条件でも、前回とおおむね同様の傾向が見られた。そのため、今回観察された問題は、少なくともサンプリングの有無だけでは説明できないと考えられる。

ただし、生成設定以外の条件や学習データの影響については、十分に切り分けられていない。

### 4. 手法の選択について

今回の結果からは、キャラクター固有の口調を再現する目的ではLoRAが有効な選択肢となる可能性が示された。一方、回答内容の自然さや一貫性、返答ルールへの追従まで含めた会話品質については、追加学習だけでなく、ベースモデルの選択やプロンプト設計も重要になると考えられる。

プロンプトやFew-shotは、それ自体で出力品質を保証するものではなく、モデルが持つ能力を引き出すための手段の一つと考えられる。

## Limitations

- 比較に使用した質問は3問のみであり、質問の種類や難易度が限られている。
- 評価は出力例に基づく定性的な観察であり、評価者間の一致や定量的な改善幅は検証していない。
- LoRAの学習データは各キャラクター約80件であり、データ量や内容が結果に与える影響は切り分けていない。
- Gemini APIとローカルLLMではモデルや生成APIが異なるため、結果の違いをモデルサイズやプロンプト手法だけの影響として説明することはできない。
- プロンプトやFew-shotの内容を体系的に変更した比較は行っていない。
- `do_sample=False` の指定によってサンプリングの影響は抑えたが、すべての生成条件を統一した比較ではない。

## Future Works

- **質問数・質問タイプの拡張：** 10〜20問程度に増やし、雑談、知識を問う質問、意見や助言を求める質問など、異なるタイプの質問で比較する。
- **プロンプトの改善：** キャラクター設定に加え、質問に直接答えること、不確かな情報を無理に作らないこと、キャラクターらしい口調と回答内容の正確さを両立することなどを指示し、出力への影響を確認する。
- **評価の定量化：** キャラクターらしさ、回答の自然さ・一貫性、指示への追従・質問への適切さをそれぞれ5段階で評価し、条件ごとの傾向を比較する。
- **モデルの比較：** 可能であれば異なる規模・特性のモデルでも同様の実験を行い、モデルの違いがキャラクター表現、回答品質、指示追従に与える影響を調べる。
- **LoRA学習の最適化：** 学習率やepochsなどのパラメータを最適化する。

## Conclusion

今回の実験では、LoRAによってキャラクター固有の口調や表現が現れやすくなる傾向が見られた一方、回答内容の自然さや一貫性には課題が残った。

また、ローカルの軽量LLMではFew-shotや返答ルールによる改善が安定しなかった一方、Gemini APIでは、同じキャラクター設定・返答ルール・Few-shot例を与えた場合に、2行以内という指示を守る出力が見られた。

これらの結果から、キャラクター会話の品質は、プロンプトや追加学習の手法だけでなく、ベースモデルの特性にも影響される可能性がある。ただし、今回は質問数が限られ、異なるモデル間の比較でもあるため、今後は質問と評価の拡充を通じて、各手法の有効性と限界をさらに検証する必要がある。
